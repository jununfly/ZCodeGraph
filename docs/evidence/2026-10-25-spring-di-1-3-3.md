## 变更明细

### Schema v5（零 DDL）

- `src/types.ts`: `NODE_KINDS` 新增 `'bean'`；`EdgeKind` union 新增 `'injects'`。
- `src/db/migrations.ts`: `CURRENT_SCHEMA_VERSION` 4→5，新增 v5 迁移条目（零 DDL，只 bump 版本 + 旧 CLI 兼容策略说明）。
- `src/db/schema.sql`: `unresolved_refs.metadata` 列注释更新（`springStereotype`/`sourceClassName`/`sourceStereotype`）。

### Bean 提取（`src/resolution/frameworks/java.ts`）

- `extractSpringBeanDiNodes()` 新增：
  - 类级 stereotype 扫描（`@Component`/`@Service`/`@Repository`/`@Controller`/`@RestController`/`@Configuration`）→ 标记 bean class，不发独立 bean 节点。
  - 方法级 `@Bean` → 发 `bean` 节点（id `bean:<file>:<line>:<methodName>`）。
  - 字段注入（`@Autowired`/`@Resource`/`@Inject`）→ 发 `injects` unresolved ref，metadata 携带 `sourceClassName` + `sourceStereotype`。
  - 构造器注入（含隐式 `@Autowired`）→ 同上。
- `scanClasses()` regex 修正：支持 `public`/`private`/`protected`/`internal`/`open`/`final`/`abstract`/`static`/`sealed`/`data` 修饰符。
- `scanMethods()` regex 修正：Java 与 Kotlin 分支分离，正确捕获返回类型。

### DI 边合成（`src/resolution/callback-synthesizer.ts`）

- `springDiEdges()` 新增：
  - 从 `injects` ref 的 metadata 建立类级 bean 索引（`sourceClassName` → `sourceStereotype`）。
  - 同包优先 + 最短 qualifiedName 消歧。
  - 边 source 为真实 class 节点 id（backfill 已重写），target 为 bean/class/interface 节点。
- `mybatisJavaXmlEdges` 改为 `CODEGRAPH_ENABLE_DATASOURCE=1` env-gated opt-in。

### Backfill（`src/indexing/rust-java-framework-routes.ts`）

- `BACKFILL_NODE_PREFIXES` 新增 `'bean:'`，保证增量索引 clean-replace。
- 插入 `injects` ref 前，将 marker fromNodeId（`bean:...`）重写为真实 class 节点 id（查 `getNodesByFile` 匹配 `kind='class' && name=sourceClassName`）。

### DB 层（`src/db/queries.ts`）

- `UnresolvedRefRow` 接口新增 `metadata: string | null`。
- `rowToUnresolvedReference()` 新增 `metadata` 字段反序列化。
- `insertUnresolvedRef()` 新增 `metadata` 列写入。

### 探针（`scripts/measure/capability-probes.mjs`）

- 新增 `probeSpringDi()`：`zcodegraph query bean --json` 期望 ≥1 bean 节点。

## 根因记录（施工中发现）

**问题**: petclinic 索引后 `injects` 边为 0。

**根因链**:
1. `extractSpringBeanDiNodes` 产出的 `injects` ref 使用 marker fromNodeId（`bean:file:line:ClassName`），但类级 bean 没有对应 bean 节点。
2. `rust-java-framework-routes.ts` 的 backfill 过滤 `newNodes.some((n) => n.id === ref.fromNodeId)` 丢弃了这些 ref。
3. 即使放行，FK 约束（`unresolved_refs.from_node_id → nodes.id`）也会拒绝插入。
4. `rowToUnresolvedReference` 没有反序列化 `metadata` 列，导致 synthesizer 无法读取 stereotype 信息。

**修复**:
- backfill 在插入前将 marker fromNodeId 重写为真实 class 节点 id（查 Rust baseline 的 class 节点）。
- `UnresolvedRefRow` + `rowToUnresolvedReference` + `insertUnresolvedRef` 补全 `metadata` 列读写。
- synthesizer 从 `injects` ref 的 metadata 直接读取 `sourceClassName`/`sourceStereotype`，不再依赖 `decorators` 列（Rust core 不填充）。
