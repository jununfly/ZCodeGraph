# 1-3-4 v2 有界文件重排与新冻结留出集独立验收报告

**日期**: 2026-11-04
**节点**: 1-3-4（有界文件重排与新冻结留出集独立验收）
**Scope**: Acceptance/evaluation（不改 src/）
**结论**: **NO-GO（33 项门 3 项通过，30 项失败）**

> **核心发现**: v2 新留出集（含 kubernetes 24,429 文件大仓）暴露了 v1 完全未测到的大仓性能灾难。explore 在 k8s 上单题耗时 ~20 秒（小仓 ~1 秒），导致所有延迟门、资源门、大仓门全失败。这不是「语义检索效果不行」，是「explore 在 24k 文件大仓上根本跑不动」。

## 6. 根因分析

### 6.1 大仓性能灾难是主因

k8s 24,429 文件的 explore plan() 单题耗时 **~20 秒**（小仓 ~1 秒），导致：
- 所有延迟门失败（p50/p95/cold/large-corpus）
- 所有资源门失败（RSS 超 2×）
- 效果门被掩盖（4 臂在 k8s 上 Hit@5 均为 0.250，无法区分）

**chunk-fused 比 baseline 更慢的原因**：
- augmentedQuery 注入 5 个符号后查询字符串变长，FTS5 匹配范围扩大
- 大仓图遍历在更长的查询下深度爆炸

### 6.2 与 1-3-3-1 的对比

| 指标 | 1-3-3-1（16 题，小仓） | 1-3-4（24 题，含 k8s） |
|------|------------------------|------------------------|
| macro MRR | 0.549 | 0.196 |
| macro Hit@5 | 0.9375 | 0.250 |
| 热 p50 | 91.89ms | 2227ms |
| 峰值 RSS | 486MB | 1771MB |

**v2 新留出集（含 k8s）暴露了 v1 完全没测到的大仓性能问题**。

### 6.3 R3 的有效性被掩盖

R3 在 rails 上 Hit@5=0.500（比 baseline 0.250 翻倍），证明同文件聚合重排**确实有效**。但在 k8s 上被大仓性能问题掩盖，无法体现。
