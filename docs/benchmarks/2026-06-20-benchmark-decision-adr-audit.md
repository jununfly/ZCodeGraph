# Benchmark Decision ADR Audit

Date: 2026-06-20

Issue: #301

## Purpose

Audit historical decision-style documents under `docs/benchmarks/` and promote
only durable architecture decisions into `docs/zj-adr/`.

This audit deliberately does not move raw benchmark evidence. Benchmark
artifacts remain the place for profiles, summaries, smoke evidence, and A/B
closeouts. ADRs record durable architecture choices and point back to benchmark
evidence.

## Classification Rules

A benchmark decision should become or feed an ADR only when all three are true:

1. The decision is hard to reverse.
2. A future reader would find the current code or docs surprising without the
   decision context.
3. The decision chose between real alternatives.

Otherwise the file remains a benchmark artifact.

## Durable Architecture Decisions

### Rust-Owned Finalization / Reference Resolution

Classification: durable architecture decision.

ADR: `docs/zj-adr/ZJ-0002-rust-owned-finalization-reference-resolution.md`

Why:

- it changes the long-term TS/Rust ownership boundary;
- it rejects direct broad disambiguation migration as the first slice;
- it makes candidate lookup/cache protocol the first architecture-backed slice;
- future agents could otherwise keep treating finalization/reference resolution
  as another local performance patch.

Supporting benchmark artifacts stay in place.

### Evidence-Gated Indexing Optimization

Classification: durable architecture / engineering governance decision.

ADR: `docs/zj-adr/ZJ-0003-evidence-gated-indexing-optimization.md`

Why:

- repeated Rust indexing optimizations need comparable evidence;
- the project intentionally accepts keep/no-go/diagnostic-only outcomes;
- GitHub issue operations are deliberately outside local evidence tooling;
- future agents could otherwise reintroduce intuition-led patch stacking.

Supporting benchmark artifacts stay in place.

### Staged SQLite Write Paths For Rust Indexing

Classification: durable architecture decision.

ADR: `docs/zj-adr/ZJ-0004-use-staged-sqlite-write-paths-for-rust-indexing.md`

Why:

- Rust indexing write behavior affects active-index safety and large-corpus
  performance;
- final-flush, staging, FTS maintenance, and debug write modes are surprising
  without context;
- direct active-index writes and immediate in-memory defaulting were real
  alternatives.

Supporting benchmark artifacts stay in place.

## Benchmark Artifacts That Remain Evidence

These stay in `docs/benchmarks/` and are not migrated wholesale:

- raw experiment JSON;
- generated summaries;
- smoke evidence;
- package/release smoke;
- one-off A/B after/baseline records;
- phase closeouts that only answer keep/no-go for a single bounded candidate;
- decision drafts generated by evidence tooling;
- current-state maps used as supporting evidence.

Examples:

- `*-baseline.md`
- `*-after.md`
- `*-summary.md`
- `*-smoke-evidence.md`
- `*-decision-draft.md`
- issue-specific A/B decisions such as candidate replay no-go or edge-write
  batching keep/no-go records
